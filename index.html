Conceptual Foundation

Understanding Multi-Tier Social Identity Registries

Large-scale government citizen registries (such as Samagra 2.0) are distributed state platforms managing millions of citizen identities, familial trees, and welfare schemes. Testing these systems requires moving beyond superficial UI checks to understand how client state, API microservices, transactional databases, and external identity gateways coordinate.

The 3-Tier Architecture & Gateway Integration Model

Every citizen action flows through three synchronized tiers and integrates with external statutory identity providers.

Tier 1 Client Browser

Angular SPA Web Portal

Manages reactive multi-step forms, client-side input validation, bilingual Hindi/English transliteration (Google Input API), and payload encryption.

QA Focus: Viewport layout shifts, touch handlers, Unicode text integrity, and silent form invalidation.
Tier 2 API Gateway

Domain Microservices (.NET)

Split into dedicated domains: Citizen Services (CitSer) for demographic mutations, and Common Services (ComSer) for master catalogs, OTPs, and workflow requests.

QA Focus: Payload serialization, AES decryption, HTTP status code accuracy (500 vs 200), and resource dictionaries.
Tier 3 Database Cluster

Relational Engine (MS SQL Server)

Structured into strict functional schemas: temporary draft tables (REQUESTS), permanent registry (SAMAGRA), and compliance telemetry (AUDIT_LOG).

QA Focus: Transaction atomicity (ACID), hard rollbacks on failure, stored procedure telemetry, and data constraints.
Gateways External APIs

Statutory Gateways

Secure API connectors to UIDAI (Aadhaar e-KYC via AUA server), Telecom SMS Gateways for OTP dispatch, and MP e-District for revenue certificates.

QA Focus: ADV (Aadhaar Data Vault) tokenization compliance, timeout fallbacks, and plain-text OTP exposures.

Environment Design: The Critical Difference Between Staging & UAT

Understanding why systems behave differently in Staging versus UAT prevents false assumptions during test execution.

Staging Environment (Mocked Sandbox) Pre-Flight
  • Echoed Credentials: OTP generation does not dispatch telecom SMS; the generated OTP is returned directly inside the HTTP response JSON for automated testing.
  • Fixed Captcha Bypass: Evaluates against a static token (TESTIN) to facilitate rapid regression testing without OCR overhead.
  • Mocked Identity: UIDAI responses are simulated or stubbed, allowing negative testing on edge scenarios without consuming live Aadhaar auth credits.
UAT Environment (Pre-Production Acceptance) Live Integrations
  • Real Telecom Gateways: OTPs must successfully traverse real telecom SMS pipelines to citizen handsets within tight validity windows.
  • Live Aadhaar Verification: Connects to statutory AUA/KUA servers; verifies biometric/OTP responses and returns masked demographic records.
  • Strict Database Constraints: Production-mirror stored procedures enforce foreign keys, schema mappings, and transaction rollbacks.

MotionPro VPN Network Tunneling

Why is VPN needed? All Staging (172.16.x.x) and UAT (172.18.x.x) servers are isolated inside the State Data Center. Connecting to the public gateway bridges your computer into the secure internal network.

Gateway Host: 103.86.26.3
Tunnel Path: /prx/000/http/localhost/welcome/index.html
Account: SAMAGRA_newstag
Client: MotionPro SSL-VPN
Mode: Full Tunnel (routes 172.16.0.0/12)
Key Principle: If MotionPro disconnects, all browser tabs on port 8088 and DBeaver SQL sessions will immediately drop.

Frontends & Swagger APIs (CitSer / ComSer)

The architecture splits backend responsibilities between two independent .NET microservices. Testers use Swagger to test APIs directly without going through the UI:

Citizen Services (CitSer)
Demographic data, member lookups, draft registration (DrtAddMember).
Staging: :8096/swagger | UAT: :8089/swagger
Common Services (ComSer)
Aadhaar e-KYC, SMS OTP dispatch, Captcha, Master lookups, RequestMaster (InsertRequest).
Staging: :8097/swagger | UAT: :8090/swagger
How UI Interacts: Angular calls ComSer to verify OTP & eKYC, CitSer to draft members, and ComSer to submit the final application.
3

Database Direct Connectivity (DBeaver)

Grey-box testing requires verifying database state behind the screen. We connect DBeaver or SSMS to MS SQL Server:

Host: 172.18.210.22 : 1433
Database: SCDNEW_2-0
Driver: Microsoft JDBC / SQL Server
Auth Modes:
• Analytical Read: SCD_USR_Read
• UAT Execution: SCD_UAT
Core SQL Check: Always query [AUDIT_LOG].[TBL_PROCEDURE_LOG] when an API returns 500 to see the exact SQL procedure error message and line number!
Essential Live Database Queries for QA Engineers (MS SQL Server)
-- 1. Inspect recent procedure execution errors (Diagnose 500 crashes):
SELECT TOP 10 CREATED_ON, PROCEDURES_NAME, LOG_LEVEL, LOG_MESSAGE, ERROR_NO, ERROR_LINES
FROM [AUDIT_LOG].[TBL_PROCEDURE_LOG] ORDER BY CREATED_ON DESC;
-- 2. Inspect members saved in temporary draft staging before final submission:
SELECT TEMP_SAMAGRA_ID, TEMP_FAMILY_ID, FIRST_NAME, LAST_NAME, DATE_OF_BIRTH, GENDER_ID, RELATION_ID
FROM [REQUESTS].[TBL_SAMAGRA_FAMILY_MEMBER_CRTN_RQST]
WHERE TEMP_FAMILY_ID = 100000606 ORDER BY CREATED_DATE DESC;
-- 3. Verify if submission committed or rolled back:
SELECT REQ_ID, MODULE_ID, TEMP_FAMILY_ID, PRIMARY_MOBILE_NUMBER, CREATED_DATE, ACTION_ID, LEVEL_ID
FROM [REQUESTS].[TBL_COMMON_REQUEST_MASTER]
WHERE TEMP_FAMILY_ID = 100000606;

The 7 Testing Dimensions of Complex Identity Registries

A structured engineering methodology covering client, API, database, security, and statutory layers.

1

UI / UX & Mobile Responsiveness

Touch events, responsive grids, input masks

Citizen portals are heavily accessed via low-cost mobile handsets. Testers must verify touch gesture abstractions:

  • Ensuring sensitive data reveal icons (e.g. eye toggle on masked Aadhaar) bind both touchstart / touchend and desktop click events.
  • Detecting responsive flexbox wrapping that causes staggered action button alignments across languages.
  • Verifying that disabled form submission states display visible validation warnings rather than silently freezing.
2

Content, Typography & Hindi Localization (i18n)

Unicode rendering, transliteration, text leaks

Bilingual governance platforms rely on real-time phonetic transliteration engines:

  • Checking that phonetic transliteration caches do not mistakenly copy First Name Hindi text into Last Name fields upon tab change.
  • Inspecting reactive form controls to ensure DOM template header strings are not inadvertently bound to demographic input models.
  • Enforcing standardized placeholder phrasing across administrative hierarchy dropdowns (District vs Zone vs Ward).
3

Business Logic & Relationship Matrices

Age gates, opposite gender constraints, life states

Social registry databases must mirror real-world statutory and legal family structures:

  • Opposite Gender Validation: Enforcing opposite gender pairing for married spouses.
  • Age Verification: Statutory marriage age enforcement (Male ≥ 21, Female ≥ 18).
  • Infant Gating: Handling infant additions <1 year without Aadhaar strictly via Civil Registration birth certificate verification.
  • Widower Deceased Check: Ensuring the prior spouse is formally recorded as deceased, and leaving spouse pointers unlinked in specific marital transitions.
4

API Contract & Decrypted Payload Verification

AES encryption, serialization, status codes

Modern government applications encrypt network requests in-flight using AES encryption:

  • Intercepting and decrypting outgoing request bodies to detect array drops (e.g., frontend omitting secondary member document attachments).
  • Validating that backend API error responses return structured, meaningful error codes rather than unhandled 500 exceptions.
  • Ensuring resource dictionaries define all application error codes to prevent missing resource lookup exceptions in production.
5

Database Transactions & Audit Integrity

ACID rollbacks, procedure telemetry, ADV compliance

Verifying that what the UI claims matches what the database commits:

  • Checking that failed submissions execute atomic ROLLBACK TRANSACTION without leaving orphaned records in request tables.
  • Inspecting AUDIT_LOG.TBL_PROCEDURE_LOG to capture the exact SQL line number and stored procedure error message.
  • Verifying UIDAI compliance: ensuring real 12-digit Aadhaar numbers are never persisted; only 18-digit tokenized REF_KEY values are stored.
6

Security & Input Sanitization

Boundary testing, length constraints, script injection

Testing backend validation against corrupted or malicious inputs:

  • Pasting 250+ characters of raw English text and punctuation into Hindi name fields to test backend sanitization rules.
  • Verifying that leading periods (. . .) in names provide helpful user feedback instead of silently breaking form states.
7

Cross-Module Workflows & Reverse-Sync Engine

Common request engine, role routing, legacy integration

Evaluating how requests transition through approval workflows:

  • Testing universal request routing through TBL_COMMON_REQUEST_MASTER via ACTION_ID and LEVEL_ID assignments.
  • Verifying asynchronous messaging queues (TBL_REVERSE_SYNC_QUEUE) that push newly approved identities to legacy databases.
Advanced Dimensions: What Software Testers Often Forget

Concurrency & Race Conditions

Rapid double-clicking "Save & Submit". Does the backend guard against duplicate primary key creation or create ghost duplicates?

Session Expiry on Preview

Waiting >15 minutes on the preview screen before final submission. Does the JWT token refresh transparently or lose all entered members?

MIME-Type Magic Byte Verification

Renaming an executable binary to .pdf. Does the backend inspect file magic bytes (%PDF-) or rely blindly on file extensions?

Network Latency Degradation

Simulating rural broadband latency (Slow 3G) in DevTools to ensure UI buttons disable during network in-flight requests.

Cross-Engine Rendering

Testing on WebKit (iOS Safari) and Gecko (Firefox) where complex Hindi Devanagari ligatures render differently from Blink (Chrome).

Aadhaar ADV Token Expiry

Ensuring that encrypted Aadhaar Data Vault tokens cannot be reused or replayed across unrelated family sessions.
